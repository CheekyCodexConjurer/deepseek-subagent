# ADR-0001: OpenCode Go through a local OpenCode server

## Decision

Use the official OpenCode CLI/server as the provider boundary. The bridge starts or attaches to a loopback OpenCode server, selects opencode-go/deepseek-v4-flash with the configured variant, submits prompt_async and consumes the event stream.

## Rationale

This reuses the user’s same-user OpenCode authentication without importing provider secrets into the bridge. It also keeps the provider implementation out of the bridge and gives the bridge a stable session/message/diff API.

## Consequences

- A managed server is a bridge-owned child and may be stopped by the bridge.
- An attached server is never stopped by the bridge.
- No model/provider fallback is allowed.
- The Codex Desktop delivery path remains a separate adapter because a healthy OpenCode server and generated Codex schemas do not prove same-chat correlation on Windows.
- Inbox delivery is durable and recoverable, but it is not equivalent to in-thread delivery.
