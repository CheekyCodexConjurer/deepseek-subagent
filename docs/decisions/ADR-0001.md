# ADR-0001: Historical provider boundary

**Status:** Superseded for new execution by the Antigravity + Gemini-only
contract documented in `docs/architecture.md`. OpenCode and DeepSeek are not
active providers. This record remains in place so the original provider
decision, data identifiers, and migration context are preserved read-only.

## Historical decision (not active)

The original bridge used an external OpenCode CLI/server as its provider
boundary. It started or attached to a loopback server, selected an
OpenCode/DeepSeek model route, submitted asynchronous prompts, and consumed
the server event stream.

The original rationale was to reuse same-user authentication without importing
provider secrets into the bridge and to keep provider implementation outside
the bridge.

## Current decision

New execution uses one provider boundary: authenticated Antigravity (`agy`)
running Gemini 3.8 Flash High through route `antigravity-flash-high` via MCP.
OpenCode and DeepSeek are not active providers. No new server, session, prompt,
or fallback may be created for a historical provider. Unknown, disabled,
unavailable, timed-out, or ambiguous execution fails closed.

The canonical MCP identity is **SubAgents MCP** with server name `subagents`.
The legacy server name, package name, CLI bins, and `deepseek_*` tool names
remain strictly protocol compatibility aliases if required by the host. They
resolve to the same canonical Antigravity/Gemini implementation and never
select a historical provider.

## Compatibility consequences

- Existing SQLite rows, result envelopes, inbox files, audit events, route
  pointers, session IDs, and flat provider/model columns are historical data.
  They are preserved strictly in read-only mode and their labels are kept
  intact. OpenCode/DeepSeek is not an active provider.
- The historical `%LOCALAPPDATA%\DeepSeek Sub-Agent` data location remains
  addressable so installation does not split or silently rename existing
  history.
- A future migration must prove quiescence, preserve the source, create and
  verify a size/SHA-256 manifest, and retain a restore path before changing
  configuration. Malformed or ambiguous data fails closed.
- Inbox delivery remains durable delivery, not provider failover. External
  orchestration remains `fallback=forbidden`.
- Installation is idempotent and does not start, stop, or kill processes in
  this patch.
- The doctor script (`scripts/doctor.ps1`) is strictly read-only and does not
  compile or generate build artifacts.

## Ownership note

The runtime implementation of this decision in `src/**`, plus user-level
Codex/Gemini governance and any already-running daemon, belongs to separate
owners. This ADR records the target and compatibility boundary; it is not
runtime activation evidence.
